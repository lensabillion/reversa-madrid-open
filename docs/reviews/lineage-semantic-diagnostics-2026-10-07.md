# Semantic origins: exact-target diagnostic plan

Recorded 7 October 2026 for `rev-h5zb`. The old optional Jev path judged a whole amendment
and attached an accepted answer to its first phrase. A request about a rejected sibling
change could therefore appear to explain wording that survived elsewhere. The new
`adopted-origin-v1` request binds each judgment to one accepted amendment/final interval
and asks about its incremental legal effect in the supplied text.

## Structural checks completed

The backend gate passed 694 tests, Ruff, strict types and 100% line/branch coverage
(4,277 statements, 1,196 branches). Independent Astra review checked exact source slices,
phrase/evidence binding, cache revision isolation, bounds, four directed dimensions,
deduplication and lexical suppression. Original v1 and v2 fixtures remain unchanged. Frontend integration passed 102 tests,
Biome, strict types and a production build. Independent review verified semantic support
metadata, graph/ranking eligibility, exact three-text cards and focused-edge method flags.

Offline request planning on four collected laws made zero provider calls and wrote no
judge cache or source data. Distinct planned targets were 6,869 for the AI Act, 2,007 for
the Data Act, 3,869 for the DSA and 1,729 for the DMA. The largest request was 23,980 bytes;
26 AI Act targets were explicitly unassessed because required context exceeded the bound.
The source run manifests retained hashes and modification times. This planning exercise
checks requests, not model behavior, retrieval recall or real-world accuracy.

## Frozen before/after comparison

The test fixture `backend/tests/fixtures/lineage/adopted-origin-diagnostics.json` contains
28 constructed cases: eight expected supporting relations, nineteen expected non-supporting
relations and one explicitly unknown relation. Four structural skips leave 24 new requests
and 23 distinct legacy requests. The corpus SHA-256 is
`597d78a05fe42ab57eaf4bc2272ae6fe042295ddfae138a2dbfa7a6e453ad644`.
The adjacent request manifest stores the exact hashes and is tested for reproducibility.

Cases cover rejected siblings, multiple surviving targets, unchanged background,
insertions outside overlap, actor/force/scope/condition/negation changes, source quotations,
paraphrases, changed final context, Unicode and unavailable old text. These labels were
constructed for software diagnostics; they are not independently collected human labels.

The optional paid comparison is prepared but has not been run. It uses the pinned
`jev-1.13.0` model, exactly 47 distinct requests, no retries or full-law generation, and a
proposed aggregate cap of $0.25. At the documented $0.042 per million input tokens,
reserving the full 65,536 tokens for every call totals $0.129368064. Human spending
approval is pending. No threshold tuning will use these examples.

## Reporting rules and limits

Report every case's old/new directed dimensions, score, decision, failure or skip; keep the
unknown case separate. Old questions concerned the whole amendment, so comparison against
surviving-target labels measures compatibility with the new task, not whether every old
answer was wrong about its broader question. Report returned usage and conservative
reserves for potentially billed failures. Do not describe synthetic diagnostic tallies as
real-world precision, calibrated confidence, recall or proof of causal influence.
